# AI 核心概念速读

下面用“帮我安排一周复习计划”作为例子。术语在不同产品中可能略有差异，重点是理解它们各自解决的问题。

## 从文字到模型

- **LLM（大语言模型）**：根据输入的上下文生成后续内容的模型。它能处理语言和代码，但生成的内容仍可能有错，需要核对。
- **Token**：模型处理文字时使用的片段单位。一个词可能对应一个或多个 Token。上下文窗口和计费通常会参考 Token 数量。
- **Context（上下文）**：模型当前可参考的信息，例如对话历史、项目文件摘要、规则和工具返回结果。上下文不是永久记忆，遗漏或过长都会影响结果。
- **Prompt（提示）**：这一次交给模型的具体任务、背景和要求。好的提示会说明目标、必要资料、限制和希望的输出。

## 从回答到行动

- **Tool（工具）**：模型可调用的具体能力，例如读取文件、运行测试或查询数据。工具会影响外部状态时，应先确认权限和作用范围。
- **Agent**：围绕目标循环工作的软件：理解任务、决定下一步、调用模型或工具、检查结果，再继续或汇报。它通常需要权限边界和停止条件。
- **MCP**：一种让 AI 应用以统一协议连接外部工具或数据源的方式。MCP 本身不是模型，也不代表连接一定安全；要检查服务器来源、可访问的数据和写入权限。
- **Agent Skill**：一份可复用的任务说明，描述在某类任务中何时使用、按什么步骤执行、遵守什么限制。Skill 通常教 Agent 如何工作，不等于给它新增底层权限。

## 一个任务怎样串起来

```text
目标：安排一周复习计划
  ↓ Prompt：课程、可用时间、优先级和输出格式
Context：已提供的课程表与偏好（受上下文长度限制）
  ↓ LLM 生成计划草案
Agent 判断是否需要查课程表
  ↓ Tool 或 MCP 读取允许访问的日历数据
Agent 检查冲突并整理结果
  ↓ 按 Skill 中的复核清单检查时长、空档和格式
输出计划；人再核对并决定是否采用
```

这不是固定架构。一个简单问题可能只需要一次 Prompt；有明确、固定步骤的任务适合工作流；需要多轮决策和工具协作时才可能使用 Agent。工具调用越强，权限和验证越重要。

## 自测

选择一个学习或生活任务，回答：模型需要哪些上下文？提示中要写清什么？哪些部分适合交给工具？如果连接 MCP，它能看到或修改什么？最后怎样独立验证结果？
