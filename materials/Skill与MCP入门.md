# Skill 与 MCP 入门

Skill 与 MCP 解决不同层面的问题：Skill 提供可复用的做事说明；MCP 为 AI 应用连接外部工具或数据。Tool 则是一次具体可调用的能力。接入任何扩展前，都应确认来源、数据访问范围和写入权限。

## 写一个小 Skill

挑选一个会重复做、容易检查的任务，例如“把一段会议笔记整理为决定、待办和未决问题”。在项目中创建 `.claude/skills/meeting-summary/SKILL.md`：

```markdown
---
description: 将会议笔记整理成决定、待办和未决问题。需要处理会议记录时使用。
---

## 步骤
1. 只依据输入记录，不补写未出现的决定。
2. 分别列出决定、待办（有负责人和日期时照录）、未决问题。
3. 对不清楚的信息标记“待确认”。
4. 输出后核对每项都能在原文中找到依据。
```

保存后在 Agent 中要求它按该 Skill 处理一小段虚构笔记。检查它是否遵守步骤、有没有编造负责人或日期。可按官方 [Skills 文档](https://code.claude.com/docs/en/skills)了解 frontmatter、目录位置和发现机制。

## 理解 MCP 的连接边界

MCP 使用客户端与服务器之间的协议，让模型应用发现并调用工具、读取资源或使用提示模板。连接某个 MCP 不代表它只读；权限取决于服务器能力、客户端授权和底层账号。优先选择可信来源、虚构数据和只读账号，避免将生产账号或个人资料交给不了解的服务。

配置前先回答：服务器由谁维护？它会读取哪些数据？能否写入、删除或执行命令？凭据保存在哪里？停止连接后如何撤销授权？若这些问题说不清，不要连接真实数据。

请按 [MCP 官方入门](https://modelcontextprotocol.io/docs/getting-started/intro)和[Claude Code MCP 文档](https://code.claude.com/docs/en/mcp)操作。协议和客户端配置会更新；不要照抄来源不明的配置命令。独立编写 MCP Server 属于选做，不是基础必做。
