# 液态玻璃前端改造施工计划

日期：2026-09-29

范围：现有答题工作台的视觉层与状态反馈；不改答题数据、题库文案、存盘规则、身份流程或文件 API。

## 方向约定

- 主方向：以 Apple Liquid Glass 的“轻、透、分层、有材质”处理固定导航和辅助面板，同时保留深蓝品牌色、系统字体和工具型信息层级。
- 使用场景：学生在自己的 Mac/Windows 电脑浏览器中长时间阅读题目、输入答案、提交附件。题干、答案输入框和主要提交按钮必须始终清楚、稳定、易读。
- 材质分工：顶部栏、答题卡/文件树侧栏、窄屏面板切换和身份首屏可用半透明背景、背景模糊、饱和度与柔和偏移阴影；题目内容、答案表单、文件行使用实底或近实底。避免玻璃层层叠放。
- 形态：提高面板与主要控件圆角；同类控件半径一致。保持题目和“提交本题”视觉优先，玻璃不承担文本对比度。
- 动效：不增加装饰性持续动效。只增加即时按压反馈和必要的状态过渡，控制在短时、可打断范围；遵从 reduced-motion。
- 兼容与无障碍：无 `backdrop-filter` 时退化为足够不透明的纯色底；增加透明度减少和高对比偏好支持；键盘焦点清晰；颜色对比不依赖玻璃模糊。
- 窄屏：保留现有题目/辅助面板切换，玻璃仅做边界与层次，不遮挡答题控件或改变信息顺序。

## 分步施工与验收

### 第 0 步：施工计划

先建立本计划并单独提交，明确范围、材质规则、功能边界和测试方式。

验收：计划通过 Markdown/差异空白检查后独立提交；不改前端文件。

### 第 1 步：设计系统与交互基线

实现 `frontend/src/style.css` 的颜色/材质/圆角 tokens、固定导航及辅助面板玻璃层、实底阅读/输入层、按钮/题号/文件操作的按压与 hover/focus/disabled 状态；增加浏览器偏好与无滤镜回退。仅在需要改变语义/结构时才调整 `frontend/src/main.ts`。

验收：`npm run build` 通过；无新增外部资源或依赖；原有身份、跳题、编辑、手动提交、删除、目录树行为未改变。构建及代码检查通过后单独提交。

### 第 2 步：桌面与窄屏视觉验收

启动本机 App，用浏览器检查桌面和窄屏，目视核对玻璃是否仅处于合适层级，文字对比和焦点状态，题目/答案是否仍为视觉主层级；检查支持 reduced transparency/reduced motion 和不支持 backdrop-filter 的回退规则。

验收：桌面与窄屏没有横向溢出；所有主要控件可操作；提交及文件树流程仍可用；渲染截图完成目检，发现问题先修复并重测，再提交修复。

### 第 3 步：文档漂移回填

实装后修订本计划的提交号、实测状态和浏览器覆盖范围，并将确认生效的 Liquid Glass 材质/形态原则回填至 `DESIGN.md`。不得改写用户原始蓝图。

验收：文档与最终 CSS 和截图一致；构建及相关测试再次通过；单独提交文档校准。是否推送远端遵从用户明确指示。
