# 身份记忆与修改施工计划

依据：用户 2026-09-29 反馈“关闭页面再打开仍要重新输入姓名学号”，并要求身份可修改，但不应成为每次打开的门槛。按项目约定先写计划，再实施、测试、逐步提交，最后校准本文档与实现的差异。不得改动原始答题蓝图或已有答题文件。

## 目标与范围

- 首次使用时登记姓名、学号；登记成功后在本设备浏览器记住身份。
- 之后重新打开 App 自动用已记住的身份读取对应本地答题资料，不再强制重复输入。
- 答题主界面提供清晰的“修改身份”入口；编辑界面预填当前姓名、学号。
- 只有服务端成功确认身份后才记住身份；本地身份记录损坏或不存在时回到登记流程，服务暂时不可用时提供重试，不静默清除身份。
- 不把姓名和学号放入 URL、日志或远端服务。说明身份保存在此浏览器的本机存储中；共享设备上可通过修改身份切换。

## 待确认的数据行为

修改姓名或学号会改变本机目录 `提交资料/<姓名>_<学号>`。不可把修改后的身份直接当作新资料加载，否则原有答案会留在旧目录而看似丢失。实施前需确认采用哪种行为：

1. 推荐：重命名当前资料目录并保留其中所有答案/附件；目标目录已存在时拒绝覆盖，提示用户处理冲突。
2. 切换资料：保留原目录不动，改为载入或新建另一身份的独立目录。

在用户确认前不实现会改变已有资料归属或目录位置的操作。无论选项如何，首次登记和再次打开自动恢复均可独立实现与测试。

### 第 1 步：身份记忆与启动恢复

修改 `frontend/src/main.ts`：启动时读取版本化的本地身份记录；有记录时调用现有 `/api/profile` 重新读取本机资料并进入答题页；首次登记成功后才写入本地存储。API 读取失败时显示可重试状态，不退回要求重新输入；存储不可用或记录格式无效时采用首次登记流程。对姓名、学号仅作本地存储，不放入地址栏。

**验收：**浏览器验证首次登记、刷新、关页重开均可恢复；清除记录后能重新登记；服务不可用时身份不丢且有重试；`npm run build` 通过。通过后提交。

**验收：**姓名和学号可编辑；取消不改变身份和答案；确认后标题/当前身份、文件树及本地身份记录一致；原答题与附件依选定策略仍可访问；目录冲突不会覆盖数据。前后端测试通过后提交。

**验收：**自动化测试和隔离浏览器流程通过；工作区无测试遗留数据。若需打包，仅在用户要求时更新发行包。通过后提交测试/实现步骤。

## 数据与隐私边界

- 本地浏览器持久化只用于恢复当前设备上的答题身份；服务端仍根据姓名和学号定位本机目录。
- 不把身份记录同步到云端，也不在每次打开时强迫用户再次输入。
- 清除浏览器站点数据会移除记忆，但不会删除 `提交资料/` 下的答题文件；可重新输入相同身份读取原资料。
- 当前用户实际答题目录属于用户数据，测试只使用临时目录；不删除、覆盖或迁移实际数据。
