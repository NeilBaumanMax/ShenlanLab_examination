# 本机提交目录恢复与身份切换施工计划

依据：用户 2026-09-29 明确要求身份不保存在浏览器，而应从本机最终提交目录 `提交资料/<姓名>_<学号>/` 识别；已有有效目录时直接进入答题页面。另要求姓名、学号仍可更改。按项目约定先提交本计划，再按步骤实现、测试、提交，最后校准文档漂移。不得改动或移动现有答题目录。

## 用户目标与行为约定

- 本机 `提交资料/` 是身份及答案恢复的唯一事实来源；不使用浏览器持久化保存姓名或学号。
- 启动时由本机 API 扫描有效的直系学生目录。没有资料目录时才显示首次登记；只有一个有效目录时自动读取并直接进入答题；有多个时显示紧凑的资料选择页，不要求重新输入姓名和学号。
- “修改身份”表单预填当前姓名和学号，可修改后继续。更换身份即使用对应的另一个 `姓名_学号` 目录；旧目录和答案保留原位、不自动合并、不覆盖。再次打开时多份资料通过选择页进入。
- 只识别目录名与其中 `学生信息.txt` 相互吻合、路径安全且为真实目录的资料；忽略符号链接、无效名或资料文件损坏的条目。扫描只读，不因启动而新建、迁移或改写目录。
- 本机 API 扫描失败时显示可重试错误，不误显示首次登记，也不要求学生重新输入资料。
- 清除此前版本可能写入的 `shenlanlab.student-profile.v1` 浏览器项；后续版本不再写入学生身份到 `localStorage` 或 `sessionStorage`。答案依旧只保存在本机文件。

**验收：**方案与用户最新描述一致，明确零/单/多份目录行为和无覆盖规则；`git diff --check` 通过。单独提交本计划。

### 第 1 步：安全列举已有本机资料

修改 `start.py` 与 `tests/test_local_api.py`，新增只读 `GET /api/profiles`。仅列举 `提交资料/` 下的安全直系真实目录；校验目录名与 `学生信息.txt` 中的姓名、学号匹配并通过现有组件校验；按稳定顺序返回必要身份字段。空目录返回空数组，损坏或不匹配的项目不暴露、不修改。

**验收：**测试空目录、单目录、多目录、排序、错误/缺失元数据、非法目录名、符号链接排除及只读不创建文件；现有 API 全套测试通过。通过后仅提交后端与 API 测试。

### 第 2 步：启动恢复、资料选择与身份修改

**验收：**生产构建通过；隔离浏览器验证零/单/多份资料路径、修改后切换、新资料首次创建、取消、切换前后旧答案目录保持不变、刷新后通过磁盘重新识别；确认浏览器存储中无身份记录。API 错误时有重试且不误显示登记表。通过后提交前端与构建产物。

### 第 3 步：文档漂移校准与交接

将本机目录自动恢复、多资料选择、改名后使用独立目录且旧目录保留、不使用浏览器身份存储的现状回填到本文档与 `docs/施工计划.md`。对照 API、测试及程序实际行为校验描述。

**验收：**`git diff --check`、`npm run build`、Python/API 全套测试通过；记录各步提交与未覆盖场景。单独提交文档校准。本轮不推送远端，除非用户明确提出。

## 隐私与数据安全边界

- 仅本地回环服务读取 `提交资料/` 的直系目录与 `学生信息.txt`；无云端账号或远程同步。
- 每次启动只读扫描；实际答案、附件只由既有提交 API 写入。切换身份不移动、删除或合并任何文件。
- 修改姓名或学号后，旧资料保留于原目录；若新目录已存在，则打开该目录已有资料，不覆盖其答案。
- 测试仅使用临时资料根目录和独立浏览器配置；不读写用户实际提交内容、不刷新用户正在使用的页面。
