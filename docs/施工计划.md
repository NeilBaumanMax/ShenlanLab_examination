# 深蓝科技部 AI Agent 闯关答题 App 施工计划

依据：仓库根目录《深蓝科技部_AI_Agent_闯关答题App_施工交接文档.md》（需求草案 v1.0，2026-09-29）。

## 施工目标与约束

交付一款可离线访问核心页面、只在本机保存答题资料的桌面浏览器 App。前端使用 TypeScript 与 Vite；运行端使用 Python 3 标准库；服务固定监听 `127.0.0.1:8765`。答题内容、身份信息和附件不得离开本机。学生完成后自行压缩个人目录并通过 QQ 邮箱提交。

不建设管理员后台、在线收件、自动评分、自动录取判断、遥测或云同步；不自动发送邮件、发布或推送。不得把学生提交资料放入源码仓库。

## 执行规则

1. 每个步骤开始前确认目标和涉及文件；完成后立即按本步骤验收点验证。
2. 验收通过后只提交该步骤相关文件，并记录提交号、验证结果和遗留事项；不把未验证的步骤混入提交。
3. 验收失败时先修复当前步骤并重测，不进入后续步骤。
4. 涉及 GitHub 远端时先检查远端分支和文件状态；保留已有内容与提交历史，不擅自覆盖或推送。
5. 所有步骤完成后逐项对照根目录施工蓝图，修正本计划和运行/交付文档中的实际漂移，并单独验证、提交文档修订。

## 分步施工与验收

### 步骤 0：仓库基线与远端核对

检查当前分支、工作区、远端地址、GitHub 远端是否已有提交或文件，以及仓库中的 `README`、`AGENTS.md`、运行配置和忽略规则。确认已有内容的归属后决定沿用或补齐，不覆盖未知内容。检查是否存在敏感文件和答题数据。

**验收：**远端状态和本地基线已记录；后续施工目录、默认分支策略及是否需要接入已有实现均明确；无文件被意外覆盖。

### 步骤 1：本施工计划

编写并校对此计划，明确功能边界、实施顺序、每步验收和交付约束。

**验收：**计划覆盖蓝图核心要求；Markdown 标题、代码格式及步骤顺序清晰。通过后独立提交。

### 步骤 2：项目骨架与安全默认值

建立或整理前端、Python 服务、内容、资料、模板和启动脚本目录；设置 `.gitignore`，确保 `提交资料/`、运行时数据、缓存、依赖和密钥不会进入版本库。初始化 Vite/TypeScript 构建配置和 Python 服务入口。

**验收：**前端依赖可安装、生产构建成功；Python 入口可运行；忽略规则覆盖提交资料和常见敏感/生成文件；启动监听地址固定为回环地址。通过后提交。

### 步骤 3：题目内容与静态界面

创建集中维护的 `content/questions.json`，覆盖 4 个阶段、10 道题和统一任务卡字段；实现路线导航、首页说明、自由跳转、资料折叠区、题目卡、状态标记、作答控件与窄屏布局。核心页面不依赖 CDN、外部字体或远程脚本。

**验收：**10 题内容与蓝图一致；所有题目可直接进入；题型和附件策略能由数据配置驱动；断网时核心页面及样式可用；桌面和窄屏基本布局可操作。通过后提交。

### 步骤 4：本地身份与答题持久化

实现姓名、学号录入及安全目录名处理；按学生建立资料目录和学生信息文件。实现题目答案保存为 `回答.md` 与结构化 `回答.json`，防抖保存、保存状态反馈、读取恢复和提交清单；不得仅依赖浏览器存储。

**验收：**中文、多行文本、空格和 URL 可保存；服务重启及页面刷新后可恢复；保存失败提示明确且不覆盖已有答案；不同学生目录互相隔离；构造的异常路径不能逃离 `提交资料/`。通过后提交。

### 步骤 5：附件上传与本地文件边界

实现按题目配置的扩展名/类型白名单与单文件大小限制（默认 50 MB），安全文件名处理、路径约束、原样保存、附件列表及移除操作。只保存文件，不执行、不解压、不联网扫描；对疑似密钥只做本机提示。

**验收：**允许类型的文件能保存并保持原始内容；禁止类型、超限文件和路径穿越输入被拒绝并显示可理解说明；拒绝上传不影响已有答案；附件只落在对应学生和题目的附件目录。通过后提交。

### 步骤 6：本地 API、提交目录操作与启动体验

完成 Python 标准库 HTTP 服务：静态资源、答题读写、附件处理、提交清单和打开个人提交目录。增加 `start.py`、Windows/macOS 启动脚本及必要的停止/端口占用提示。启动时检查 Python 版本、建立数据目录、等待服务就绪并打开浏览器；固定端口 `8765`，端口占用时清楚报错，不静默换端口。

**验收：**全新环境按启动说明启动后能打开页面；服务仅绑定 `127.0.0.1`；端口冲突可理解地失败；“打开提交目录”定位正确；源码中不存在向外发送答题资料的请求。通过后提交。

### 步骤 7：随包讲义、模板与运行说明

制作蓝图列出的资料索引、核心概念、Agent 安装、Git 分支、Skill/MCP、常见问题、项目说明模板、AI 使用记录模板和 `.gitignore` 示例；补齐学生运行说明，解释 Python 准备、启动/停止、恢复进度、附件限制、目录压缩和邮件提交方式。动态资料仅保留官方或指定外链。

**验收：**所有本地链接和启动命令与实际文件吻合；说明没有将某一 Agent 安装路线写成唯一选择；安全边界、同一解压目录恢复要求和手工邮件提交均明确。通过后提交。

### 步骤 8：集成验收与缺陷修复

从全新启动流程执行蓝图第 7 节验收项，覆盖断网核心流程、保存恢复、隔离、附件格式/大小、路径安全、GitHub URL 或 ZIP、目录打开、自由跳关、刷新、窄屏及重复保存/上传。按发现逐项修复，每组相关修复先重测再提交。

**验收：**蓝图验收项逐条有通过证据；未完成项和原因明确记录；所有必要构建或自动检查通过。通过后提交。

### 步骤 9：文档漂移校准与最终交付核对

将实际实现、运行方式、文件树、限制和验收结果逐项对照施工蓝图、运行说明及本计划；只对确有差异的文档做修正，并记录尚未实现的蓝图内容，避免文档声称未交付功能已完成。核对 Git 状态、提交资料忽略规则和本地提交序列。

**验收：**文档与可运行产物一致；所有漂移已修正或标为未完成；敏感信息和学生答题资料未进入版本库；最终工作区干净或剩余改动已明确归因。通过后提交。
