# 答题工作台改造施工计划

依据：用户 2026-09-29 描述的答题者视角目标，结合现有本地 App 实现制定。此计划先于本轮功能代码提交；执行时每一步先实现、再验收，通过后只提交该步内容。功能完成后再回校本文档与《施工计划.md》，记录实测结果及剩余差异。

## 用户目标

- 打开 App 首先填写姓名和学号；个人提交目录使用“姓名_学号”命名。
- 每题对应一个目录；答案文本、GitHub 链接和其他文字使用 `.txt` 文件，图片、压缩包等原文件平铺在该题目录中。
- 每题由学生显式点击“提交本题”保存；提交后可以继续修改并覆盖，再次提交更新文件，也可以手动删除答案或附件。
- 右侧持续显示个人目录与目录下的自动生成文件和用户提交文件，并提供打开系统文件管理器的按钮。
- 右上区域有实时十题答题卡；题号可跳转，未作答、未提交、有未提交修改、已提交状态清晰。题目始终可重做，不锁关。
- 界面去除非必要说明和装饰文字，突出题目内容、答案区和主要操作。

## 落盘与交互约定

- 新目录：`提交资料/<姓名>_<学号>/`；姓名、学号仍做路径分隔符与危险字符校验。
- 每题文件夹内直接放置自动生成的 `回答.txt`、字段文本（如 `GitHub仓库链接.txt`）和学生附件原文件；不再新建 `附件/` 子目录，不再以 JSON/Markdown 作为学生可见答案格式。
- 根目录自动生成 `学生信息.txt`。右侧目录树展示根文件和所有题目目录内容；当前题目可删除其答案/附件，删除需确认。
- 老版本的 `<学号>_<姓名>` 目录和其 `回答.json`、`回答.md`、`附件/` 内容需可恢复并安全迁移；若新旧目录同时存在，不自动合并或覆盖，向学生明确报错并保留两边数据。
- 输入期间只更新内存草稿和答题卡状态；显式提交时校验本机密钥提示、保存答案与已选择附件，然后刷新目录树和已提交状态。跳题不自动提交，草稿仍保留在当前运行内存；刷新/关闭前未提交的草稿明确提示无法恢复。
- 文件目录区域显示路径和文件名；“打开目录”调用现有本地 API，由 macOS 打开 Finder、Windows 打开资源管理器。
- 十题答题卡以提交状态实时呈现，可随时跳转。桌面保留固定右侧工作面板；窄屏改用可切换面板或经用户确认的适配形式，不能挤压答案输入区。

## 分步实施、测试与提交

### 第 0 步：本施工计划

写清产品目标、文件格式、数据兼容策略、每步边界及验收。原始蓝图保持不变。

**验收：**目标与用户描述逐项对应；步骤顺序明确；`git diff --check` 通过。单独提交本计划。

### 第 1 步：本地目录与文件 API

调整 `start.py` 及 `tests/test_local_api.py`：姓名在前的目录命名；根目录学生信息 TXT；每题 `回答.txt` 和字段 TXT；附件落在题目目录根部；提供可安全枚举的文件树与受限删除 API；保留打开个人目录能力。实现旧数据检测/迁移，冲突时拒绝写入并保留原文件。

**验收：**API 测试验证新目录名、TXT 内容/覆盖、GitHub 链接 TXT、附件原字节及平铺路径、文件树反映自动和上传文件、删除后文件确实消失、旧格式安全迁移、目录冲突不覆盖、路径穿越拒绝、打开目录仍工作。测试通过后提交。

### 第 2 步：身份首屏与显式逐题提交

调整 `frontend/src/main.ts`、`frontend/src/api.ts` 与相关类型：进入路线前要求填写身份并恢复本机进度；移除自动保存，显式“提交本题”按钮一次保存本题文字与待上传附件；题目间切换不触发提交；修改已提交题目的草稿标为未提交修改，再提交覆盖对应 TXT；支持删除本题答案/文件并确认；离开或刷新有未提交草稿时提醒。

**验收：**姓名/学号未完成时不能进入答题；相同身份可恢复旧答案；不同身份隔离；编辑不落盘，点击提交后落盘；修改后覆盖旧 TXT；敏感信息提示仍在本机且能阻止误提交；删除可用，失败有提示；`npm run build` 与 Python/API 全套测试通过。通过后提交。

### 第 3 步：答题卡、实时文件树与界面精简

调整 `frontend/src/main.ts`、`frontend/src/style.css`：右上显示可点击的 1–10 题号卡片，明确空白/已提交/有修改状态；右侧显示学生目录树、文件名和打开目录按钮；提交、上传、删除后即时刷新；精简装饰及解释文案，题目、答案与提交动作保持视觉主层级；适配桌面和窄屏。

**验收：**十题任意跳转、编辑后状态即时变化；当前题文件树与磁盘 API 一致，根级与题目级文件可见，打开目录调用系统文件管理器；删除/重提后树和答题卡同步；桌面及窄屏无横向溢出且输入、提交可用；键盘焦点与状态有可读标签；构建、API 测试及浏览器流程通过。通过后提交。

### 第 4 步：运行与交付说明

更新 `运行说明.md`、资料索引中相关提交说明及必要的答题说明：身份首屏、姓名学号目录名、手动提交、草稿刷新风险、TXT/附件布局、文件树/删除/打开目录行为与手工压缩邮件提交。

**验收：**文档示例路径和实际目录一致；本地链接校验通过；无自动保存或旧文件布局的误导。通过后提交。

### 第 5 步：文档漂移与交接校准

在实现与验收提交后，对照本计划、`docs/施工计划.md`、蓝图和可运行产物，回填每步提交号/测试结果/未测项目，修复实现或说明中的漂移。原始蓝图不改；未跟踪的用户蓝图不自动加入提交。

**验收：**文档与测试/实际目录结构一致；全套构建和 API 测试通过；工作区变化均可解释；逐步提交完成后再推送更新至 SSH 远端。

## 风险与边界

- 新命名不能让既有答题消失，因此迁移必须可回滚且不能覆盖并存目录。
- 未提交草稿保留在当前页面内存，但不会跨刷新/服务重启恢复；界面须清晰提示并在离开时确认。
- 删除是本机不可逆操作，必须明确目标并让文件树反映结果。
- “打开文件资源管理器”按系统调用 Finder/Explorer；浏览器不能直接读任意本机文件内容，目录面板由本地服务返回安全文件名清单。
